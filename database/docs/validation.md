# 검증 기록

검증일: 2026-11-02

실행 환경: 임시 메모리 DB의 PGlite 0.5.14 / PostgreSQL 18.6 엔진. 별도 서비스 설치 없이 PostgreSQL 문법과 제약조건을 실행했다. 실제 팀 서버나 운영 DB에는 접속하지 않았다.

## 확인한 결과

| 항목 | 결과 |
|---|---|
| 001_init.sql 전체 실행 | 성공 |
| 테이블·컬럼 수 | 17개·100개 |
| 외래키 제약 | 24개. 과제·버전과 완료·버전의 복합 FK 포함 |
| 정의서의 컬럼·자료형·필수 여부 | SQL 생성 결과와 비교 |
| 001_verify.sql | 예시 전·후 실행 성공 |
| 002_constraints.sql | 잘못된 입력 거부 24건 및 정상 입력·트리거·선택 FK 검사 통과 |
| 001_demo_data.sql | 성공. 잔액 150, 풀이 3회, 가구 1개 |
| 생성 SQL 재실행 | 이미 존재하는 스키마 오류로 중단, 기존 자료 유지 |
| 예시 SQL 재실행 | 중복 사용자 오류로 중단, 기존 자료 유지 |

24개 거부 사례는 음수·누락 잔액, 음수 가격, 아이디 중복·형식, 잘못된 역할, 중복 수강, 수료 시각 누락, 존재하지 않는 사용자 참조, 중복 가구·문제 완료, 완료 문제와 버전 불일치, 과제와 풀이 버전 불일치, 중복 요청, 단계 키 규칙, JSON 객체 형식, 출제일 이전 마감, 중복·음수 보상, 중복·0원 거래, 참조 중인 과정 삭제를 포함한다.

정상 입력 검사에는 과제 없이 독립적으로 푸는 경우, 단계별 답변, 다른 사용자의 같은 작업 번호 사용, 한국 날짜 시작 시각의 마감, 두 updated_at 트리거, 구매 목표 상품 삭제 시 선택 해제를 포함한다.

## 범위

이 검증은 초기 SQL·예시·검사 파일에 대한 것이다. 일반 PostgreSQL 서버의 접속 설정·사용자 권한, 프런트 연결, 인증·서버 채점, 동시 구매·보상 처리, 실제 데이터 이관은 검증하지 않았다. PostgreSQL 16·17에서의 별도 실행도 수행하지 않았으므로 팀의 실제 버전에서 동일 검사 파일로 재확인한다.

제약 검사는 [checks/002_constraints.sql](../checks/002_constraints.sql), 조회는 [checks/001_verify.sql](../checks/001_verify.sql)로 재현할 수 있다. 제약 검사는 검증용 임시 행을 마지막에 ROLLBACK하므로 정상 완료 후 그 행은 남지 않는다.
